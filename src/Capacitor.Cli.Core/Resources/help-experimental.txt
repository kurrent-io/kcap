kcap experimental — Opt in to experimental features

Usage: kcap experimental [subcommand]

Subcommands:
  list                    Name the profile, then show each feature, whether it is on, and whether the
                          daemon has applied it (default)
  enable <feature>        Turn a feature on for the profile in use
  disable <feature>       Turn a feature off for the profile in use

Features:
  codex-app-server        Run Codex reviewers and interactive Codex agents over codex app-server instead
                          of the terminal. Needs Codex 0.146.0 or later. On Windows it applies to a
                          profile that never set it; disable it to keep that profile on the terminal
  in-app-pages            Open kcap Pages inside the desktop app instead of the browser, where interactive
                          pages can be answered. macOS, and Windows with the WebView2 runtime. Read by the
                          desktop app, not the daemon, so the list shows it as desktop app only and
                          enable/disable do not wait to confirm
  launcher-next-work      Show the server's next-work suggestions under the desktop launcher, as the web
                          dashboard does, and start a session from one. Needs a server with next work
                          turned on. Desktop app only, like in-app-pages

The profile in use is the one KCAP_PROFILE names, or else the active profile
A change reaches the running daemon without a restart; kcap waits a few seconds for it to confirm.
Agents already running keep the transport they started with.
